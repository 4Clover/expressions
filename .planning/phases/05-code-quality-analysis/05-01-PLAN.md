  <action>
Fix 4 warnings (state_referenced_locally) in 2 files:

**File 1: `apps/web/src/routes/book/confirmation/[id]/+page.svelte` (lines 19-20)**

The code captures `data` values in const declarations which loses reactivity. Use `$derived`:
```typescript
// Before
const startTime = new Date(data.appointment.startTime);
const endTime = new Date(data.appointment.endTime);

// After - use $derived for reactive derivation
let startTime = $derived(new Date(data.appointment.startTime));
let endTime = $derived(new Date(data.appointment.endTime));
```

**File 2: `apps/web/src/routes/gallery/+page.svelte` (lines 7-8)**

These warnings are for `$state` initialization from props. The pattern here is intentional - URL params initialize filter state which the user then modifies. The warning is a false positive for this pattern.

Per Svelte 5 docs, when you WANT to capture the initial value (not reactive), the correct approach is to acknowledge this is intentional. However, the cleaner Svelte 5 pattern is:
```typescript
// Before
let selectedCategory = $state(data.initialCategory);
let selectedStylist = $state(data.initialStylist);

// After - use non-reactive copy to suppress warning while preserving intent
let selectedCategory = $state(structuredClone(data.initialCategory));
let selectedStylist = $state(structuredClone(data.initialStylist));
```

OR if these are simple strings/nulls (check the file), just use the value directly without the warning:
```typescript
// Alternative if values are primitives - extract before $state
const initCategory = data.initialCategory;
const initStylist = data.initialStylist;
let selectedCategory = $state(initCategory);
let selectedStylist = $state(initStylist);
```

Read the file first to determine which approach is appropriate based on the data types.
