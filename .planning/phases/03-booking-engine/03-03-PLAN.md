Create POST endpoint following RESEARCH Pattern 3:

**Request body:**
```typescript
{
  serviceId: string;
  staffId: string;
  startTime: string; // ISO datetime
  endTime: string;   // ISO datetime
  customerName: string;
  customerEmail: string;
  customerPhone?: string;
}
```

**Logic:**
1. Parse and validate request body
2. Validate required fields (return 400 if invalid)
3. Use database transaction:
   a. Check for conflicts (overlapping confirmed appointments)
   b. If conflict found, return 409 with helpful message
   c. Generate cancelToken with nanoid
   d. Insert appointment with status 'confirmed'
   e. Return appointmentId

**Response:**
- 201: `{ success: true, appointmentId: string }`
- 400: `{ error: 'validation', message: string }`
- 409: `{ error: 'conflict', message: 'This slot was just booked. Please select another time.' }`
- 500: `{ error: 'server', message: string }`

Use `import { nanoid } from 'nanoid'` for cancel token generation.

Handle "Any Available" staffId:
- If staffId === 'any', find first available stylist for the time slot
- Use the actual staffId in the insert

  <done>Appointments can be created via POST /book with conflict detection</done>
