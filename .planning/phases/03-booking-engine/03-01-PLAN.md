  <name>Task 1: Create appointments schema with optimistic locking</name>
  <files>packages/db/src/schema/appointments.ts, packages/db/src/schema/index.ts</files>
  <action>
Create appointments.ts with:

1. **appointmentStatusEnum** - pgEnum with values: 'pending', 'confirmed', 'cancelled', 'completed', 'no_show'

2. **staffSchedule table** - Weekly availability per stylist:
   - id (uuid, pk, defaultRandom)
   - staffId (uuid, FK to staff.id, notNull)
   - weekday (integer, 0-6 for Sun-Sat, notNull)
   - startTime (text, format "09:00", notNull) - Use text, not time type (Drizzle quirks per RESEARCH)
   - endTime (text, format "17:00", notNull)
   - isActive (boolean, default true)
   - Add unique constraint on (staffId, weekday)
   - Add RLS policy for public read access

3. **appointments table**:
   - id (uuid, pk, defaultRandom)
   - staffId (uuid, FK to staff.id, notNull)
   - serviceId (uuid, FK to services.id, notNull)
   - startTime (timestamp with timezone, notNull)
   - endTime (timestamp with timezone, notNull)
   - status (appointmentStatusEnum, default 'confirmed')
   - version (integer, default 1) - For optimistic locking
   - customerName (text, notNull)
   - customerEmail (text, notNull)
   - customerPhone (text, nullable)
   - cancelToken (text, notNull, unique) - nanoid for cancel URL
   - cancelledAt (timestamp with timezone, nullable)
   - depositRequired (boolean, default false)
   - depositAmount (integer, nullable) - cents
   - depositPaidAt (timestamp with timezone, nullable)
   - createdAt, updatedAt timestamps
   - Add RLS policy: public can view own appointments by cancelToken
   - Add RLS policy: authenticated can manage appointments

4. **Relations**:
   - staffScheduleRelations: one staff
   - appointmentsRelations: one staff, one service

5. Update index.ts to export all new tables, enums, and relations.

Use the existing import pattern from staff.ts and services.ts.
